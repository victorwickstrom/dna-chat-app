# Internationalization (i18n)

DNA Chat Assistant supports multiple languages using i18next with react-i18next bindings.

## Configuration

i18next is configured in `src/i18n.ts`:

```typescript
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import enTranslation from './locales/en/translation.json'
import svTranslation from './locales/sv/translation.json'

i18n.use(initReactI18next).init({
  resources: {
    en: { translation: enTranslation },
    sv: { translation: svTranslation },
  },
  lng: 'sv', // Default language
  fallbackLng: 'en', // Fallback if key missing
  interpolation: { escapeValue: false },
})

export default i18n
```

The configuration is imported in `main.tsx` to initialize before the app renders.

## Translation Files

Translation files are located in:

```
src/
  locales/
    en/
      translation.json
    sv/
      translation.json
```

### File Structure

Translations are organized by feature/component:

```json
{
  "appTitle": "DNA Chat Assistant",
  "chat": {
    "placeholder": "Ask about inflammation, neurodiversity, or diet...",
    "send": "Send",
    "sending": "Sending...",
    "emptyState": "Start by asking a question about your genetics."
  },
  "preferences": {
    "title": "Settings",
    "explanationLevel": "Explanation Level",
    "save": "Save settings"
  }
}
```

## Language Switcher

The `LanguageSwitcher` component (`src/components/LanguageSwitcher.tsx`) allows users to change languages:

```typescript
import { useTranslation } from 'react-i18next'
import { useGlobalContext } from '../context/AppContext'
import { savePreferences } from '../storage'

const LanguageSwitcher = () => {
  const { i18n } = useTranslation()
  const { preferences, setPreferences } = useGlobalContext()

  const handleChange = async (lang: 'sv' | 'en') => {
    await i18n.changeLanguage(lang)
    const updatedPrefs = { ...preferences, language: lang }
    setPreferences(updatedPrefs)
    await savePreferences(updatedPrefs)
  }

  return (
    <div className="flex items-center gap-2">
      <button onClick={() => handleChange('sv')}>SV</button>
      <button onClick={() => handleChange('en')}>EN</button>
    </div>
  )
}
```

The component:

1. Gets current language from i18n
2. Calls `i18n.changeLanguage()` to switch
3. Updates preferences in context
4. Persists to IndexedDB

## Using Translations in Components

### Basic Usage

```typescript
import { useTranslation } from 'react-i18next'

const MyComponent = () => {
  const { t } = useTranslation()

  return (
    <div>
      <h1>{t('appTitle')}</h1>
      <p>{t('chat.placeholder')}</p>
      <button>{t('chat.send')}</button>
    </div>
  )
}
```

### With Interpolation

```json
{
  "greeting": "Hello, {{name}}!"
}
```

```typescript
<p>{t('greeting', { name: 'User' })}</p>
// Output: "Hello, User!"
```

### Accessing i18n Instance

```typescript
const { t, i18n } = useTranslation()

// Get current language
const currentLang = i18n.language // 'sv' or 'en'

// Change language
await i18n.changeLanguage('en')
```

## Adding a New Language

1. Create a new folder in `src/locales/`:

   ```
   src/locales/de/translation.json
   ```

2. Copy structure from existing translation file and translate:

   ```json
   {
     "appTitle": "DNA Chat-Assistent",
     "chat": {
       "placeholder": "Fragen Sie nach Entzündung, Neurodiversität oder Ernährung...",
       "send": "Senden"
     }
   }
   ```

3. Import in `src/i18n.ts`:

   ```typescript
   import deTranslation from './locales/de/translation.json'

   i18n.use(initReactI18next).init({
     resources: {
       en: { translation: enTranslation },
       sv: { translation: svTranslation },
       de: { translation: deTranslation }, // Add German
     },
     // ...
   })
   ```

4. Update `LanguageSwitcher` to include the new option.

5. Update the `Preferences` type to include the new language:
   ```typescript
   language: 'sv' | 'en' | 'de'
   ```

## Common Pitfalls

### Missing Translation Keys

If a translation key is missing, i18next returns the key itself:

```typescript
t('nonexistent.key') // Returns: "nonexistent.key"
```

**Solution**: Always add keys to all translation files. Use TypeScript to catch missing keys at compile time.

### Forgetting to Wrap Text

Hardcoded strings won't be translated:

```typescript
// ❌ Wrong
<button>Send</button>

// ✅ Correct
<button>{t('chat.send')}</button>
```

### Nested Key Typos

Typos in nested keys are easy to miss:

```typescript
// ❌ Wrong (typo in 'preferences')
t('prefereces.title')

// ✅ Correct
t('preferences.title')
```

### Not Persisting Language Choice

Language should be saved to preferences:

```typescript
// ❌ Wrong - only changes i18n, lost on refresh
i18n.changeLanguage('en')

// ✅ Correct - persists to IndexedDB
const handleChange = async (lang: 'sv' | 'en') => {
  await i18n.changeLanguage(lang)
  await savePreferences({ ...preferences, language: lang })
}
```

### Dynamic Content in Translations

Avoid putting JSX inside translations:

```typescript
// ❌ Wrong
t('message.with.link')  // "Click <a>here</a>"

// ✅ Correct - use Trans component
import { Trans } from 'react-i18next'
<Trans i18nKey="message.with.link">
  Click <a href="/link">here</a>
</Trans>
```

## Best Practices

1. **Use namespaces** for large apps to organize translations
2. **Keep keys descriptive**: `preferences.save` not `btn1`
3. **Test both languages** when adding new UI
4. **Use fallback language** to avoid blank text
5. **Extract strings early** - don't wait until the end
